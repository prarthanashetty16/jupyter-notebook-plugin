# Phase 6 probes: mechanisms behind the known time biases (and two RAM gaps)

Every probe uses its own synthetic data (never benchmark points), states its hypothesis in the
docstring and was run on the development machine (Windows 11, 16 logical CPUs, Python 3.12.5,
pandas 3.1.1, numpy 2.5.5, no pyarrow), **on mains power** (the first runs of the time probes were
partly on battery and were repeated; the mechanisms held, the absolute speeds rose). Raw output is next to each script (`*.out`).
A mechanism enters a model only if its probe confirmed it.

| known bias (dev, frozen models) | probe | mechanism found | model change |
|---|---|---|---|
| concat of category-heavy frames ~5-11x UNDER (time) | `p_concat_category.py` | categoricals whose categories DIFFER are materialised as `str` (pointers to the categories' string objects): 12-14 ns per row and column vs < 1 ns when the categories agree; at 10% cardinality the objects do not fit in cache (object take 5-6 ns at 1k-10k distinct objects, 58-65 ns at 1-3M) | `_time.concat`: copy at the working set + an object take per row for object columns and for categoricals with differing categories (Tier 1 compares the categories) |
| groupby 2.6x OVER, astype->category 1.4x over / 0.25-0.5x under at high cardinality | `p_hash_workingset.py` | factorize cost per row rises with the distinct count G (int64 4.7 -> 74 ns, str 27 -> 407 ns from G = 100 to 3M); groupby (`sort=True`) and astype("category") also sort the G uniques, which is why they cost 2-3x factorize at high G | `_time.groupby` / `_time.astype` / `_time.drop_duplicates` / `_time.merge`: factorize at the (Tier 1) distinct count + G log2 G sort of the uniques; Tier 0 = geometric middle of the extremes |
| read_csv 0.3x UNDER on text / dates, 3x OVER on numeric | `p_csv_astype_matmul.py` | per FIELD by parsed type: 9-14 ns numeric, 154-188 ns text or dates (dates are read as text by default; distinct or repeated text alike); the frozen model divided bytes by one rate | `_time.read_csv`: rows x (numeric fields x c_num + text fields x c_text) at Tier 1; Tier 0 (types unknown) uses the geometric middle |
| astype -> str: float 0.35x UNDER, int 1.4x over, datetime 0.7x | `p_csv_astype_matmul.py` | per source dtype: int 92-97 ns, datetime 177 ns, float 368 ns per element | profile scalars `int/float/datetime_to_str_s` |
| float32 matmul 2.2-3x OVER | `p_csv_astype_matmul.py` | sgemm runs at 2.6-3.0x the float64 flop rate; one BLAS thread gives 59 vs 214 GFLOP/s (3.6x scaling on 16 logical CPUs) | profile curves `blas64_flops` / `blas32_flops` by product size |
| concat category-heavy RAM 23% LOW | `p_concat_category.py` (tracemalloc), `p_concat_category_ram.py` (OS peak, 362-831 MiB) | differing categories: each such column becomes 8 B/row of pointers (instead of 1-4 B/row of codes) and the converted pieces of the column being concatenated (8 B/row) are alive with the result: `moved - codes + 8 n c + 8 n`; tracemalloc 10.7 B/row/col at c = 3 (= 32/3); OS peak 539 / 831 MiB measured vs 554 / 858 derived (+3%), while `moved` alone (402 / 628) is 25% under; identical categories: unchanged (362 / 553 measured vs 402 / 628, the existing model) | `ConcatModel` Tier 1 (it compares the categories): low / expected as derived; Tier 0 unchanged (its high, two copies, already covers the case) |
| select_columns saving over-predicted (46-59% vs 13-19%) | `p_merge_select_columns.py` (OS peak, unique / fan-out / half-overlap keys) | the saving of dropping unread columns follows which phase sets the peak: unique N:1 join (pandas skips the left copy, key factorisation dominates) 184 -> 176 MiB = **5%** (peak just under the 200 MiB bar); fan-out x2 550 -> 188 MiB = **66%**; half overlap (left rows taken) 276 -> 122 MiB = **56%**. The benchmark's select_columns cells were near-N:1, so ~13-19%; the suggestion re-estimate runs the merge model at Tier 0, which charges a left copy and therefore a width-proportional saving | none: documented limitation (a re-estimate at Tier 1 that knows the left-copy elision and the output rows is the derivation it points to; it needs its own suggestion check); the rule stays off |
